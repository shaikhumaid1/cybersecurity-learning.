## Documentation standard

Each practical should include:

1. Aim
2. Requirements — including the purpose of each tool
3. Procedure — step-by-step commands and explanations
4. Result — actual observations and outputs

Where relevant, the documentation also includes:

- Investigation context and evidence source
- Screenshots with sensitive information redacted
- Hash values and verification details
- Interpretation of results
- Tool limitations and acquisition errors
- Beginner-friendly explanation and cybersecurity relevance

## Evidence handling

- Preserve original evidence and work on authorized test media or forensic copies.
- Record hashes and acquisition details where applicable.
- Document unreadable sectors, incomplete scans and other limitations.
- Do not publish private data, credentials, complete forensic images or unnecessary device identifiers.
- Clearly label synthetic training data and illustrative authentication results.
